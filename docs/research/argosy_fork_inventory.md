## Q1. What is in the fork folder, and what state is the code in?

### Takeaway
The folder is a Claude-Code-driven fork of rommapp/argosy-launcher v2.15.1. It has 22 commits on a local `fork` branch (2026-09-11 to 2026-09-26) that replace almost all of the presentation layer (about 11k added lines, mostly new files). The commits also fix real bugs in the download queue, Steam, file writes and startup, and patch the vendored LibretroDroid for GameCube. ### Inferences
- The fork is small in "logic" terms. Apart from the presentation layer, its substantive non-UI changes are about 300 lines: the download queue and Steam fixes, the file-write guard, the startup fix and the Dolphin LibretroDroid patches. A Linux rebuild therefore has to recreate upstream Argosy's entire non-UI stack (RomM sync, downloads, save sync, emulator launching) plus the fork's UI. The fork's UI cannot be ported on top of an existing Linux core.
- The local `origin/main` ref has probably not been fetched since 2026-09-10. "0 behind" therefore says nothing about how far upstream has moved since then.

### Gaps
- Upstream's current head and changes since v2.15.1 were not checked (no network fetch was done).
- The published design canvas (a claude.ai artifact linked from CLAUDE.md L49 and L214) was not read. CLAUDE.md says its essentials are reproduced inline, but rejected tile-art options and the exact board details exist only on the canvas.
- Why the Task numbering skips 7 (FORK-NOTES mentions Tasks 2–6, 8 and 9) is not recorded.

## Q2. What does upstream Argosy provide, which the fork kept and the Linux app must therefore re-implement?

### Takeaway
Upstream Argosy is a complete, gamepad-first Android RomM client: library sync, on-demand ROM and BIOS downloads, bidirectional save and state sync with conflict handling, achievements, collections, emulator auto-detection and launch (external apps and a built-in libretro frontend), multi-disc handling, Steam/GameNative games, Jellyfin and music playback, and more. Every fork screen sits on top of upstream ViewModels and services, so none of this came from the fork, but all of it is part of the parity bar.

### Cited Findings
- **Upstream features (README):** native RomM client with IGDB-rich metadata; automatic ROM and BIOS downloads sorted by platform with a queue; bidirectional save sync with conflict detection; RetroAchievements display; custom and smart collections ("Top Unplayed", "Recently Added", "Most Played") pinned to home; gamepad-first; YouTube video wallpaper; ambient audio (background music); themes, blur, saturation and opacity backgrounds, box-art styles, UI sound effects; emulator auto-detection; RetroArch core selection per platform; multi-disc disc picker; L3 Quick Menu (search, random, most played, top unplayed, recent, favorites); R3 Quick Settings (theme, haptics, UI sounds, BGM, performance mode and fan control on supported devices); library filtering (genre, players, franchise, region); game stats; user ratings synced to RomM; offline mode; image caching; Steam games via GameHub/GameNative; app launcher; in-app updates; first-run wizard; favorites; hide games — [src/README.md](src/README.md)
- **Listed external emulators:** RetroArch, PPSSPP, DuckStation, AetherSX2, Dolphin, DraStic, melonDS, Mupen64Plus FZ, Pizza Boy, Lime3DS, Azahar, Flycast, Redream — [src/README.md](src/README.md)
- **RomM API surface the client uses** (Retrofit interface): `api/heartbeat`, `api/platforms[/{id}|/identifiers]`, `api/roms[/{id}|/identifiers]`, `api/roms/{id}/content/{fileName}`, `api/roms/{fileId}/files/content/{fileName}`, `PUT api/roms/{id}/props`, `api/firmware/{id}/content/{fileName}`, `api/collections` (+ `/smart`, `/virtual`, CRUD), `api/saves` and `api/states` (GET/POST/PUT/delete, `/{id}/content`, `/{id}/downloaded`), `api/sync/negotiate`, `api/sync/sessions[/{id}][/complete]`, `api/devices` (GET/POST/PUT), `api/auth/device/init`, `api/auth/device/token`, `api/client-tokens/exchange`, `api/users/me`, `api/users/{id}/ra/refresh`, `api/permissions/me`, `api/play-sessions`, `api/activity/heartbeat` (POST/DELETE), `api/screenshots` (+ `/{id}/content`), `api/search/cover`, `api/music/tracks`, `api/music/{facet}` — [src/app/src/main/kotlin/com/nendo/argosy/data/remote/romm/RomMApi.kt](src/app/src/main/kotlin/com/nendo/argosy/data/remote/romm/RomMApi.kt)
- **Auth model:** RomM supports scoped client tokens with a device pairing flow. The rule is "use one for the device — never the admin password." Pairing shows an 8-character code ("Scan to pair") that a RomM user approves via `GET /api/auth/device/pending/<CODE>` and `POST /api/auth/device/approve` — [CLAUDE.md L255-257](CLAUDE.md); [FORK-NOTES.md L286-292](FORK-NOTES.md)
- **Download state model:** `DownloadManager.state: StateFlow<DownloadQueueState>` with states QUEUED, WAITING_FOR_STORAGE, DOWNLOADING, EXTRACTING, MOVING, PAUSED, COMPLETED, FAILED, CANCELLED. Updated every 500 ms in memory and every 5 s to the DB. "Installed" is `localPath != null || isExternallyManaged` — [FORK-NOTES.md L330-343](FORK-NOTES.md)
- **Multi-disc model:** disc completion writes `game_discs.localPath`, and when all discs are present it writes `games.m3uPath`. It never sets `games.localPath` — [FORK-NOTES.md L341](FORK-NOTES.md)
- **Library folding:** Argosy merges RomM sibling rows that share a display name into one game with a version picker, joins per-disc rows into one multi-disc game, drops rows with a different name but the same IGDB/Moby/RA id as an earlier row, and does **not** read `missing_from_fs` — [server-notes/2026-09-14-romm-investigation-summaries.md L11, L109-113, L202](server-notes/2026-09-14-romm-investigation-summaries.md)
- **Server zip and m3u handling:** a multi-file RomM row downloads as a server-built zip that Argosy unzips. Argosy deletes any `.m3u` that arrives in the zip and writes its own only from discs at the folder's top level — [server-notes/2026-09-14-romm-investigation-summaries.md L196-206](server-notes/2026-09-14-romm-investigation-summaries.md)
- **Sync filters:** hides tags starting "proto" or names containing "(proto" (`RomMSyncFilter.kt:150-153`); filters `.srm`; region and hack filters are configurable on the device — [server-notes/2026-09-14-romm-plan-skeptic-review.md, Confirmed 13 and Risky 10](server-notes/2026-09-14-romm-plan-skeptic-review.md)
- **Built-in emulator (upstream):** vendored LibretroDroid; cores downloaded as unpinned nightlies from the libretro buildbot (android arm64) with an update-check worker; global settings in a DataStore plus per-platform overrides; global and per-game core-option tables; shaders (None, Sharp, CUT×3, CRT, LCD, Custom chain), filter, aspect, integer scaling, rotation, overscan crop, black frame insertion, fast-forward, rewind (forced off on "heavy" platforms), bezels ("frames"), auto save/restore state, rumble, analog/d-pad mapping, touch controls, HUD and speedrun keys; BIOS copied to the system dir, with launch blocked without BIOS only for Saturn, 3DO, TG-CD, PC-FX, CD-i and Sega CD — [server-notes/2026-09-14-nova-argosy-inventory.md L3-37](server-notes/2026-09-14-nova-argosy-inventory.md)
- **Registered cores for the owner's systems:** PS1 pcsx_rearmed* and mednafen_psx_hw; SNES snes9x* and bsnes; GBA mgba*, vbam, vba_next and gpsp; GC/Wii dolphin; Dreamcast flycast; PSP ppsspp; PS2 none (routed to external ARMSX2/NetherSX2) — [server-notes/2026-09-14-nova-argosy-inventory.md L28-37](server-notes/2026-09-14-nova-argosy-inventory.md); [CLAUDE.md L290-293](CLAUDE.md)
- **External app launch:** ARMSX2 gets a VIEW intent with a FileProvider `content://` URI and nothing else. GameNative gets `app.gamenative.LAUNCH_GAME` with `app_id` and `game_source`. Launch arguments are stored per platform in `emulator_launch_args` — [server-notes/2026-09-14-nova-argosy-inventory.md L67-70](server-notes/2026-09-14-nova-argosy-inventory.md)
- **Dreamcast emulator order:** Redream, then Flycast app, then built-in Flycast core. The built-in core gets a real path (so .cue/.gdi find their tracks); external apps get a single-file content:// URI — [server-notes/2026-09-14-romm-investigation-summaries.md L192](server-notes/2026-09-14-romm-investigation-summaries.md)
- **Save sync internals** (upstream docs): sigil reads a ROM and returns `title_id`, `save_id` and a `usage` (FOLDER_EXACT, FOLDER_PREFIX, FILE_EXACT, FILE_PREFIX, FOLDER_SPLIT). Per-platform handlers (3DS, PS2, PSP, Vita/Wii/WiiU, GameCube GCI, Switch, PS3, Xbox 360, Xbox, RetroArch file default `<base>/<rom name>.srm`) turn it into paths. The doc warns that "a changed archive shape invalidates every save already on a server." Save states follow a separate rule, `<states base>/[<content dir>/]<core dir>/<rom name>.state<N>` — [src/docs/save-id-to-path.md L1-25, L312-330, L364-380](src/docs/save-id-to-path.md)
- **Upstream-declared fragile zones:** save sync (needs live-data proof, `GET /api/saves`, negotiate no_op twice), RA hardcore compliance, native libretrodroid, and the social, netplay and music domains — [src/AGENTS.md "Fragile zones"](src/AGENTS.md)
- **Other upstream subsystems the fork touched or relies on:** Steam downloads via JavaSteam (`SteamService`, `SteamContentManager`, depot downloader); Jellyfin full-screen player (`ui/screens/player/PlayerEngine.kt`); ambient BGM with refcounted `holdVideoSilence()` / `releaseVideoSilence()`; `ImageCacheManager` (RomM assets cached to files, read by Coil); a screen dimmer; the sync monitor; GPU driver downloads (Settings > Drivers); dual-screen companion — [FORK-NOTES.md L345-359, L492-497](FORK-NOTES.md); [server-notes/2026-09-14-nova-argosy-inventory.md L61-65](server-notes/2026-09-14-nova-argosy-inventory.md); [git log main](src/)

### Inferences
- For a Linux client, the hardest parity items are upstream's, not the fork's: save sync that interoperates with Argosy (same `api/sync/negotiate` protocol and the same save-id-to-path and archive shapes, so saves round-trip between the Nova on Android and the Nova on Linux), the device pairing and token flow, sibling and multi-disc folding, and download/extract/m3u handling.
- Upstream's RetroArch-oriented save path rules (`<rom name>.srm`, sorted state folders) map naturally to RetroArch on Linux. Standalone emulators on Linux (PCSX2, Dolphin, PPSSPP, DuckStation) use different save locations from their Android builds, so the path registry has to be rebuilt for Linux.

### Gaps
- The full list of upstream settings sections (17 are reachable from the fork hub) and the exact semantics of `api/sync/negotiate` were not traced. The second needs reading `SyncCoordinator` and `SaveSyncOrchestrator` in `src/`.
- The sizes of the netplay, social, QuayPass and music subsystems (all dropped from the fork drawer) were not assessed.

## Q7. Bugs, pitfalls and design decisions a Linux rebuild should inherit

### Takeaway
The notes record a set of hard-won rules: protect save data above all, never let UI imply progress that has not happened, treat the accent as a signal, key video and audio behaviour to selection settling, reconnect and resume background work on startup, guard every write choke point, make silent failures loud (logging), and verify on the real device. Most are platform-neutral and should become requirements or tests in the Linux project.

### Cited Findings
- **Save sync is sacred:** "Do not touch save sync… Breaking it silently loses game saves" (rail 3). Upstream calls it "incredibly complex"; changes need live-data proof (`GET /api/saves`, negotiate no_op twice) — [CLAUDE.md L471-473](CLAUDE.md); [src/AGENTS.md "Fragile zones"](src/AGENTS.md)
- **Directory-clobber bug:** a file write with overwrite semantics deleted a whole emulator memory-card directory. Guard at the single choke point, and test that normal overwrites and creates still work ("A guard that broke normal saves would be worse than the bug") — [git commit 989da755](src/); [FORK-NOTES.md L498](FORK-NOTES.md)
- **"A guard added to one path is unfinished"**: enumerate every path to the same mutation — [src/AGENTS.md "Handling user data that looks wrong"](src/AGENTS.md)
- **Startup responsibilities hidden in a replaced screen:** replacing the home screen silently dropped the RomM connect, the weekly library auto-sync and the favourites refresh. Restored by calling upstream's delegate, not by reimplementing it — [FORK-NOTES.md L499](FORK-NOTES.md)
- **Download queue pitfalls:** an optimistic "Preparing" state counted against a shared slot budget (self-deadlock); a progress tick republishing a stale object reverted the state to QUEUED; concurrent queue processing started two writers on one temp file; the queue was not retried when the server connection came back — [FORK-NOTES.md L492-493](FORK-NOTES.md)
- **Silent library logging:** JavaSteam's SLF4J with no provider hid every failure for three sessions, so forward third-party logs — [FORK-NOTES.md L497](FORK-NOTES.md)
- **TLS trust-manager interplay:** pinning certain hosts to system CAs changed which TLS APIs work; the fix was protocol choice (TCP), not weakening pinning — [FORK-NOTES.md L497](FORK-NOTES.md)
- **Selection-driven media:** change metadata instantly but debounce video start (~200–300 ms; 250 ms used); the video cuts and never fades (a fade delays the audio); crossfade text against moving video (~90 ms), keeping the outgoing text; stop preview video and audio under the screensaver and when backgrounded; hold BGM silent while a preview plays, and release only a hold you took — [WORK-ORDER.md L139-146](WORK-ORDER.md); [CLAUDE.md L226-232](CLAUDE.md); [FORK-NOTES.md L417](FORK-NOTES.md)
- **Resource URLs on cold start:** build media URLs from the saved server address when the live connection is not up yet — [FORK-NOTES.md L534](FORK-NOTES.md)
- **Crop analysis pipeline:** request once per list, batch results (750 ms), use timeouts, three tries then centre, never re-run on download ticks — [FORK-NOTES.md L417](FORK-NOTES.md)
- **Manual cache bounds:** 100 MB cap, 40 MB per file, `.part` cleanup, 600 px pages (later 900 px in the saver) — [FORK-NOTES.md L417, L535](FORK-NOTES.md)
- **Multi-disc correctness:** "installed" must consider the playlist/m3u, not just a single local path; progress must aggregate discs (last-write-wins per game shows one disc's progress) — [FORK-NOTES.md L341-342](FORK-NOTES.md)
- **Comma-joined metadata columns split names containing commas** (9 franchise/collection names); related-games SQL using substring LIKE must match whole tokens — [CLAUDE.md L218-221](CLAUDE.md); [FORK-NOTES.md L553](FORK-NOTES.md)
- **Dangerous-neighbour actions:** when a menu's row list changes, keep focus on the same action (QUIT → RESET slide). Taps on a conflict's cover must not resolve a save conflict; only explicit choices act — [FORK-NOTES.md L428, L432](FORK-NOTES.md)
- **Status honesty:** queued save transfers must not show as UPLOADING in the accent with a bar; "SCAN with save sync off said 'up to date'" was wrong; show raw failure text — [FORK-NOTES.md L428](FORK-NOTES.md)
- **In-game core-option pitfall:** toggling per-game settings, or "reset option", sends menu defaults to the running core (e.g. `dolphin_defer_efb_copies=disabled`), so relaunch before judging — [server-notes/2026-09-14-nova-settings-challenge.md L7-10](server-notes/2026-09-14-nova-settings-challenge.md)
- **Missing shader file:** a chain whose file is missing silently falls back to no shader — [FORK-NOTES.md L125](FORK-NOTES.md)
- **Libretro core logs** (tag `Libretro Core`) are the first place to look before blaming a core build; one stray stored core option (software renderer) caused a total GameCube crash — [FORK-NOTES.md L68-92](FORK-NOTES.md)
- **Library hygiene interacts with the client:** stale missing rows show as dead tiles; rows whose files moved stay downloadable-but-broken until cleanup, so do moves right before the scan and cleanup; dated prototype names are not hidden by the "(proto" filter — [server-notes/2026-09-14-romm-plan-skeptic-review.md "Risky" 6, "Confirmed" 13](server-notes/2026-09-14-romm-plan-skeptic-review.md)
- **Server-side multi-disc conventions:** do not use .m3u on the server; the client writes its own playlist; GDI multi-disc unpacked into one folder overwrites generic track names — [server-notes/2026-09-14-romm-investigation-summaries.md L198-204](server-notes/2026-09-14-romm-investigation-summaries.md)
- **Achievements:** shown only from RomM's per-game `ra_metadata`; if RomM has not matched a game to RA there is nothing to show — [CLAUDE.md L155-157](CLAUDE.md)
- **Design decisions to inherit:** the four-state file indicator; accent reserved for motion and selection; no fake chrome; 4:3 framing everywhere; the preview video as the only audio; the Browse panel as "one element at two heights"; plain cover in a white hairline; screensaver content rules — [CLAUDE.md L47-238](CLAUDE.md)

### Inferences
- These translate into concrete Linux requirements: a single file-write abstraction with a directory guard and tests; a queue state machine with a mutex and explicit retry-on-reconnect; mandatory structured logging from every third-party library; an "app startup" service independent of any screen; per-disc-aware install state.

## Q8. Testing approach, build pipeline and agent workflow conventions worth reusing

### Takeaway

### Inferences
- Items 2, 3, 4, 5, 7, 14 and 15 in "Beyond" are largely solved by building on desktop RetroArch, PCSX2, Dolphin and PPSSPP under gamescope rather than a custom libretro frontend. Items 10–13 are client-side data-handling improvements needing no server changes. (Inference.)
- Parity items 11–13 (save interoperability with Android Argosy) are the highest-risk part of the rebuild. They should be specified from upstream's `SyncCoordinator`, `SaveSyncOrchestrator` and `save-id-to-path.md` before any UI work. (Inference.)

- Linux-side equivalents for GameNative/Steam on armadaOS (presumably the native Steam client in Game Mode) are not covered by these notes.
